# Checkpoint 2026-11-15: Lune 1.0.0-beta.1 "Nouvelle Lune"

State of the project before the first measurements on a Vita: what was checked, how, what was
found and fixed, what remains unverified, and the test plan for the console.

## What was checked

| Check | Result |
|---|---|
| Build for the Vita (VitaSDK, GCC 15.2, `-Wall -Wextra`) | builds; the remaining warnings are in code inherited from upstream (possible truncation of long paths, an unused function, checks that are always true) |
| CI (GitHub Actions) | build, PC tests and VPK publication green |
| PC tests, AddressSanitizer + UBSan | 129 checks, all passing: pacing (31), settings file (71), SPS rewrite (14), helpers (13) |
| Interface preview, 12 scenarios × 3 languages, AddressSanitizer + UBSan + leak check | no memory error, no undefined behaviour, no leak; all text fits but one game name in Spanish (cut with an ellipsis, as intended) |
| cppcheck 2.13 (warning, style, performance, portability) | findings reviewed; real ones fixed (below) |
| GCC static analyzer (`-fanalyzer`) on the whole app | findings reviewed; real ones fixed (below) |
| Code review of every change since xyzz 0.13.2 | threads, locks, buffers and state machines read again |
| Survey of the other forks | [design/forks.md](../design/forks.md) |

## Found and fixed

| Problem | Where | Consequence before the fix |
|---|---|---|
| Direct display mode drew without a lock | `src/video/vita.c` | at a pause, the decoder thread and the menus could drive vita2d at the same time (corruption or crash) |
| Stream end handled by two threads at once | `src/connection.c` | `LiStopConnection()` could run twice when the PC ended the stream while the menus did |
| Quit the game from the pause | `src/gui/ui_connect.c` | raced the PC-side end and fell back to the home screen |
| 5th and 6th front-touch fingers | `src/input/vita.c` | written past a 4-point array |
| SPS rewrite failure | `libgamestream/sps.c` | the decoder received a corrupted SPS (a byte cut) or the previous one |
| Cover downloader was a kernel thread using a pthread mutex | `src/gui/boxart.c` | the crash pattern seen by dubleyu with `sem_timedwait` |
| Pairing error codes | `libgamestream/client.c` | `(ret = f() != OK)` returned 1 instead of the error |
| Double `fclose` | `src/check_dir.c` | undefined behaviour at start-up when the data folder falls back |
| `sscanf("%s")` into 256-byte buffers | `src/input/mapping.c` | overflow with a long line in a mapping file |
| `h264_free()` did not free `slice_data` | `third_party/h264bitstream` | 16 bytes leaked per stream |
| Rename a PC to `.` or `..` | `src/device.c` | its folder moved out of the data folder |
| Non-stereo audio | `src/audio/vita.c` | buffers sized for stereo (the stream is always stereo today) |
| Settings file values out of range | `src/config.c` | used as is; now reset to their defaults |
| *Paced* display, first version | `src/video/pacing.c` | simulations showed frames missing their flip (the drawing budget was not counted), the delay passing its maximum, and the anchor oscillating across a refresh with a matched rate; reworked and covered by tests |

Removed: the customisable hotkeys module inherited from 0.13.2 (`src/gui/hotkey.c`, `ui_hotkey.c`):
its menu was never called and its shortcuts were never checked during a stream; only its start-up
file read ran, always from `ux0:data/moonlight` whatever the data folder.

Also cleaned up: interface preview's fake drawing pool freed per frame (it hid real leaks), internal
"phase 2" labels, Spanish developer scripts replaced by `tools/dev`, obsolete files removed (man page,
release script, old screenshots, a developer's IP address).

Not fixed, noted: upstream code still has warnings about possibly truncated paths (4 KB key folder
in 512-byte buffers; real paths are short); the PC scan thread reads the PC list without a lock (the
menus stop the scan before changing the list); motion units and axes are the original ones
(NowaLone's fork changed them; to check on a Vita first).

## Identity

The project is named Lune, version 1.0.0-beta.1 "Nouvelle Lune". It has its own title ID
(`LUNE00001`, found in no Vita project on GitHub; VitaDB could not be queried from the build machine),
its own data folder (`ux0:data/lune`) and its own LiveArea icon: it installs next to Moonlight, and a PC
paired with Moonlight must be paired again. The VPK was checked: `param.sfo` holds `LUNE00001` and
`Lune`, the LiveArea text shows `LUNE` and `v1.0.0-beta.1`, the images are 8-bit indexed PNGs.

## Not verified

Nothing in this version has run on a Vita yet. In particular: every timing and smoothness claim,
the *Paced* display on real Wi-Fi, the YUV texture layout (taken from juanjsebgarcia, who checked it),
the reading of the Wi-Fi power-save and Bluetooth settings from the registry, the stream restart
from the pause (Sunshine must accept the resume right after the previous stream ends), the pairing
under the Vita's nickname, the new bubble and LiveArea, the creation of `ux0:data/lune`.

## Test plan on the Vita

Same game, same place, 3 to 5 minutes per session, *Statistics while streaming* on. Each session
leaves `ux0:data/lune/stats/session-<date>.csv` and `.txt`.

1. **Install**: the VPK installs as a new *Lune* bubble next to Moonlight; the LiveArea shows the moon,
   `LUNE` and `v1.0.0-beta.1`; Moonlight still starts with its own PCs and settings.
2. **Start-up and menus**: the home screen shows *Lune*, `v1.0.0-beta.1` and the build; warnings if
   Wi-Fi power saving or Bluetooth is on; `ux0:data/lune` exists.
3. **Pairing**: search the network, type the code in Sunshine; the Vita appears under its nickname in
   Sunshine; the PC shows as paired after restarting Lune.
4. **Profiles**, one session each: *Smooth*, *Paced*, *Lowest latency*, *Original*.
5. **One option at a time** from *Smooth*: *Wait for late packets* off then 30 ms; *Fast colour
   decoding* off; *Spread work over the cores* off; *Video packet size* 1392; *Read the controls in
   step with the Vita* off. Change the option from the pause (START + L + R) and accept the restart.
6. **Robustness**: pause and resume ten times; quit the game from the pause; quit it on the PC during
   a stream; turn the Wi-Fi off during a stream; put the Vita to sleep during a stream and wake it up.
7. **Touch**: in mouse mode, keep a finger on the screen while pausing (the click must be released on
   the PC); five fingers on the screen in tablet mode.

To send back: the `.csv` and `.txt` files, one sentence per session on the feel (stutter, input lag,
sound), and any crash dump (`ux0:data/psp2core-*.psp2dmp`).
